# 豫见河南 UI 共创实录：从概念稿到可演示产品（含问题复盘与 SOP）

## 1. 项目背景

本次项目目标是做一个用于录课演示的 PC Web 原型：**“豫见河南”旅游推荐系统**。  
核心要求不是讲算法细节，而是讲完整产品体验闭环：

`选点 -> 推荐 -> 路线 -> 结果`

技术栈与实现策略：

- Vue 3 + Vite + ECharts（演示友好）
- 纯前端 Mock 数据（稳定可控）
- 伪地图拓扑图（开发快、视觉可控）

---

## 2. 设计目标与约束

### 2.1 目标

- 10~15 分钟内能讲清价值
- 中国风统一视觉
- 交互逻辑真实：用户可选起点/终点/必经点，结果与路径联动
- 算法“隐身在产品背后”：Dijkstra 做能力支撑，不喧宾夺主

### 2.2 约束

- 录课优先，演示稳定优先
- 无后端依赖
- 页面需中文化且信息密度适中

---

## 3. 关键交互决策（最终版）

### 3.1 三段式选择模型

在“智能推荐”页将交互统一成一个景点卡片区，不拆三块表单：

1. 出发景点（单选）
2. 结束景点（单选）
3. 必经分支点（多选）

并增加自动去重规则：

- 起点、终点不能重复
- 必经点不能与起点/终点重复

### 3.2 流程化高亮

顶部流程状态条与卡片角标同步：

- `始`（起点）
- `终`（终点）
- `经`（必经）

用户在同一组卡片内操作，标签变化代表角色变化，避免“分区重复选择”造成认知负担。

---

## 4. 视觉系统演进（中国风）

### 4.1 导航栏从普通条到古风卷轴

最终导航特征：

- 古风底图 + 蒙版（保证可读）
- 每个导航项使用不同剪影背景（山形/屋檐/城门/桥/亭）
- 当前页通过深色蒙版高亮
- 全局同步到 5 个页面并保持高亮一致

### 4.2 首页 Hero 专业化

优化点：

- 删除冗余 CTA（“立即开始推荐/查看示例路线”）
- 保留高价值信息：标题 + 副标题 + 两个主题标签
- 清理不和谐大色块，降低视觉噪声

### 4.3 行程结果页结构修复

修复内容：

- 解决主图与下方攻略卡叠压
- “导出攻略图/分享行程”按钮移入主图区域
- “行程结果”标题放入图内，形成完整头部视觉组
- 删除“豫见”红字章元素，避免无意义装饰干扰

## 5. 典型问题复盘（技术视角）

### 5.1 自动布局导致坐标失效

现象：节点移动到新容器后，`x/y` 修改不生效。  
原因：父容器为 flex/auto layout。  
处理：将父容器改为 `layout: none` 后再精确定位。

### 5.2 子遮罩尺寸未同步导致黑边

现象：行程结果页下方出现黑色竖条。  
原因：父容器改宽后，内部遮罩仍是旧宽度。  
处理：同步更新遮罩宽高到父容器尺寸。

### 5.3 高亮与信息层级冲突

现象：导航高亮存在“对不上”“可读性弱”。  
处理：统一胶囊尺寸、等宽网格、文字颜色对比、蒙版透明度标准化。

### 5.4 装饰元素过度

现象：卷轴角、小点、底纹叠加后显得杂。  
处理：保留剪影背景 + 蒙版，删去小点与多余横杠，控制细节密度。

## 7. 最佳实践 SOP（可复用）

### SOP-1 先定叙事，再定页面

1. 明确录课主线（产品体验优先还是技术原理优先）
2. 固定页面闭环（建议 4 页）
3. 再补算法解释位（不要先堆算法控件）

### SOP-2 交互先做“单入口统一选择”

1. 同一景点池承载全部角色选择
2. 角色通过状态流转，不通过区域拆分
3. 统一做自动去重校验

### SOP-3 视觉层级用三层就够

1. 背景层：低对比古风纹理
2. 内容层：卡片/图表/地图
3. 交互层：高亮、按钮、状态标签

### SOP-4 任何容器改尺寸，必须联查子层

检查清单：

1. 内部 mask 宽高是否同步
2. 绝对定位子元素是否越界
3. 圆角、描边、阴影是否被裁切

### SOP-5 全局导航一次建模，多页复用

1. 先做一个“标准导航母版”
2. 复制到各页面
3. 仅改高亮项，不改单项尺寸与间距

### SOP-6 录课前冻结版本

1. 固定数据集（景点、边权、路径结果）
2. 固定状态流（起点->终点->必经）
3. 固定演示脚本（每页讲什么、停几秒）

---

## 8. 结语

这版“豫见河南”最大的收益，不是某个单点样式，而是把“算法能力”嵌进了“用户可感知的旅程决策”。  
当界面、交互和叙事路径统一后，Dijkstra 就不再是抽象名词，而是用户点击后能立即感知的价值结果。
