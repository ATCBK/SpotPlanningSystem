# 动态路径演示分阶段修复设计

## 1. 背景

当前项目的“智能推荐”和“路径详情”页已经具备基础的动态路径演示能力，但存在两个影响答辩表达的问题：

- 多个节点在向最终布局收拢时容易重合，尤其是同城景点围绕同一城市锚点展示时。
- 探路过程更像“边一次性出现”，没有明确表现“从当前点出发，逐一比较候选，再确认最优边并进入下一个点”的算法过程。

本次修复目标是在不推翻现有 `DemoScene` 结构的前提下，增强动画表达力，并让演示更符合 Dijkstra 探路讲解口径。

## 2. 目标

- 消除动态路径演示中的节点重合问题，保证最终节点布局稳定可读。
- 在推荐页和路径详情页中统一呈现“当前点高亮 -> 候选边试探 -> 最优边胜出 -> 进入下一点”的过程。
- 保留现有 `RouteDemoCanvas` 与 `DemoScene` 的主体结构，降低改动风险。
- 通过自动化测试覆盖节点唯一性和阶段化事件输出，避免回归。

## 3. 方案选择

经过对现有实现的分析，本次采用“混合方案”：

- 保留 `DemoScene` 的基础字段：`nodes`、`probeEdges`、`rejectedEdges`、`finalEdges`、`totalDuration`
- 新增“阶段化事件列表”作为演示时间轴
- 由 `RouteDemoCanvas` 根据时间轴事件驱动节点和边的样式变化

这样既能兼容现有页面接线方式，也能把算法过程拆得更清楚。

## 4. 数据模型设计

### 4.1 节点布局

景点节点不再仅依赖“围绕城市锚点做微小固定偏移”，而改为：

- 先按城市分组
- 同城景点围绕城市锚点按扇形或环形分布
- 依据组内索引计算角度和半径
- 对不同城市保留稳定锚点，对同城内节点产生可预测且不重合的位置

这样可以保证：

- 同城节点不会堆叠到同一个位置
- 不同刷新和重播之间视觉一致
- 推荐页景点图和路径页城市图都能复用同一套“稳定布局”思路

### 4.2 阶段化事件

新增事件序列，例如：

- `focus-node`：当前节点成为算法正在处理的点
- `probe-edge`：当前节点向候选节点发起试探
- `reject-edge`：某条候选边被判定为非最优并淡出
- `choose-edge`：本轮胜出的边被确认
- `settle-node`：到达并确认下一节点

这些事件将包含：

- 作用对象 ID
- 起止时间
- 事件类型
- 所属 segment / step

`RouteDemoCanvas` 会在现有逐帧播放基础上，根据当前时间窗读取事件并计算节点与边的状态。

## 5. 页面呈现设计

### 5.1 智能推荐页

- 仍使用景点级节点
- 重点展示“当前景点如何向候选景点试探”
- 同城候选若存在多个景点，仍以稳定布局展开，避免重叠
- 选中的下一跳保留高亮，未选中候选边做短暂停留后淡出

### 5.2 路径详情页

- 使用城市级节点
- 强调 Dijkstra 试探、比较、确定最短边的过程
- 当前城市高亮最强，已访问城市保留“visited”状态
- 候选边与淘汰边在样式上明显区分

## 6. 视觉与交互规则

- 当前节点：放大、高亮、标签完全显示
- 候选节点：轻度高亮
- 已确认节点：保留激活状态但弱于当前节点
- 未选中节点：低透明度背景态
- 试探边：逐条绘制
- 淘汰边：先显示后淡出
- 胜出边：颜色更深，持续保留直到下一阶段

## 7. 测试策略

新增或强化以下回归测试：

- 节点坐标唯一性：同一路径下节点最终坐标不得重复
- 阶段事件存在性：场景中必须包含候选、淘汰、胜出等关键事件
- 顺序正确性：事件应满足“先试探，再淘汰/确认，再进入下一节点”
- 现有总时长和最终路径边数量仍符合原有预期

## 8. 风险与控制

- 风险：事件模型与现有渲染逻辑耦合不清，导致动画不同步
  控制：保留现有边集合字段，仅将事件作为增强层引入

- 风险：节点布局改动影响现有视觉截图
  控制：优先保持城市锚点不变，只调整同城展开方式

- 风险：页面文案和编码问题干扰验证
  控制：先聚焦动画与布局逻辑测试，再做页面级回归

## 9. 验收标准

- 推荐页与路径详情页的动态演示中，不再出现明显节点重合
- 可以清楚观察到“当前点 -> 多候选试探 -> 最优边胜出 -> 进入下一点”的过程
- 自动化测试通过，且不破坏现有路径结果输出

## 10. 第二轮重设计补充

基于后续评审截图，本次动画需要进一步收敛为“连续探路型”：

- 同一时刻只允许一个当前点
- 候选边必须逐条出现，不允许并发铺开
- 已确认主路径持续保留，但历史路径标签不常驻
- 候选线比主路径更细，主路径箭头明显收窄
- 节点、线宽、箭头、标签字号按容器尺寸做同比例缩放，保证小屏与大屏位置关系一致
